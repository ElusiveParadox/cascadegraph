# CascadeGraph engineering contract

CascadeGraph is a source-backed retry analyzer, not an AI safety verdict.
Read this file, relevant scoped instructions, DECISIONS.md, PROGRESS.md and
TASKS.md before editing.

## Boundaries
- Python/FastAPI owns parsing, normalization, graph invariants and simulation.
- React owns presentation; use the generated API client.
- Never run uploaded code, install uploaded dependencies, or evaluate Python.
- Compose `depends_on` and networks do not prove HTTP calls.
- Preserve original retry semantics, source spans and unresolved values.
- Keep simulated and measured results separate. Never fabricate evidence.
- AI sees bounded, redacted, explicitly opted-in source, with no tools/secrets.
- Only the committed sample app runs in Docker, on GitHub Actions, not Replit.
- PostgreSQL is live storage; explicit SQLite is local/test-only. Preserve
  anonymous ownership and retention. Production schema changes belong to Publish.

## Delivery
Use feature branches and Conventional Commits. Do not rewrite main or platform
remotes. Rebase against an existing remote main before merging; never bypass
failed CI or call an unmerged PR merged. Bootstrap an empty remote with a small
foundation commit before feature PRs. Keep active work in TASKS.md; completed
work and actual executed checks in PROGRESS.md. Explain architecture changes in
DECISIONS.md. No secrets, raw uploads, generated reports or dependency folders
in Git. Keep files focused and tests next to domain concerns.

## Verification
Run `uv run --frozen pytest`, `uv run --frozen ruff check src tests`,
`pnpm run typecheck`, and frontend unit checks. Use existing managed artifact
workflows. Test parser negatives, hostile archives, timeout/deadline semantics,
determinism, session isolation, and deletion. A Compose file is not evidence
that Compose ran: retain the actual CI run and report.

## Phases
Foundation → complete sample/archive MVP → measured Compose validation →
release/security/documentation. No speculative framework expansion or Rust
optimization before correctness and real validation. Publication requires the
user's approval. Real developer feedback cannot be generated by an agent.
